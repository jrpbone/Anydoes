# Anydoes V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the complete offline-first Anydoes v1 Flutter planner with responsive task management, deterministic scheduling, transactional persistence, notifications, and safe `.dayplan` portability.

**Architecture:** Feature-first Flutter presentation uses Riverpod controllers over domain repository contracts. Drift provides transactional local persistence; scheduling, recurrence, validation, and portable-file logic remain pure Dart services so they can be exhaustively unit tested.

**Tech Stack:** Flutter 3 / Dart 3.12, Material 3, Riverpod, Drift with `drift_flutter`, `file_selector`, `path_provider`, `flutter_local_notifications`, `flutter_timezone`, `timezone`, `crypto`, `uuid`, `intl`, and Flutter test tooling.

## Global Constraints

- Work without accounts, a backend, or a network connection.
- Support phone, tablet, and desktop layouts without platform-specific feature gaps.
- Use a default planning horizon of 14 days, configurable from 7 to 30 days.
- Begin planning at the next five-minute boundary.
- Use task session defaults of 25 minutes minimum and 90 minutes maximum.
- Keep proposed schedule blocks out of persistent storage until accepted.
- Generate recurring occurrences only through a rolling 90-day horizon.
- Serialize instants in UTC and weekly availability as local wall-clock rules.
- Use one versioned UTF-8 JSON `.dayplan` format with `full_backup` and `shared_list` kinds.
- Apply proposal acceptance and import/restore mutations transactionally.
- Preserve touch, mouse, keyboard, semantic-label, contrast, text-scaling, focus-order, and reduced-motion usability.
- Require confirmation for replace restore, task-bearing list deletion, and removal of future blocks after task completion.
